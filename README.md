# Telegram-бот с простой админкой

## Что умеет

- `/start` отправляет приветствие и две inline-кнопки;
- ответы и названия кнопок меняются через админ-панель;
- администратор создаёт рассылку, видит предпросмотр и подтверждает либо отменяет её;
- рассылка идёт всем, кто хотя бы раз использовал `/start`;
- в рассылке есть кнопка «Подробнее», возвращающая к приветствию и двум кнопкам.

## Настройка

```bash
cp .env.example .env
nano .env
```

Заполните `BOT_TOKEN` и `ADMIN_USERNAMES` через запятую. Например:

```env
ADMIN_USERNAMES=anna,@ivan_petrov
```

`@` необязателен; регистр букв не важен. Администратор обязан иметь публичный
Telegram username. При каждом запуске бот сверяет `ADMIN_USERNAMES` с таблицей
пользователей SQLite и обновляет флаг администратора в базе. Конфиг остаётся
единственным источником прав.

> Username удобен, но его можно поменять или удалить в Telegram. Тогда доступ
> автоматически пропадёт до исправления значения в `.env`. Пользователь без
> username админом быть не сможет.

## Админка

После `/start` пользователь из `ADMIN_USERNAMES` получает обычное приветствие и
отдельное сообщение «Админ-панель». Также ему доступна команда `/admin`; другим
пользователям она ничего не показывает.

Админка меняет тексты сразу в SQLite. Изменения переживают перезапуск. Значения в
`.env` — исходные тексты для чистой базы данных.

## Docker-запуск

```bash
docker compose up -d --build
```

На старом Debian используйте:

```bash
docker-compose up -d --build
```

Логи:

```bash
docker-compose logs -f
```

SQLite-база лежит в `data/bot.db`; её не следует удалять, если нужно сохранить
пользователей и тексты из админки.
